YAML Flight Path System
=======================

This file explains how new UAV flight paths can be created, added, selected, executed, and analyzed using YAML files.

The purpose of this system is to allow users to create new flight paths without editing the core execution scripts.

Normal users should only create or edit YAML files inside the path_specs/ folder. The scripts inside the scripts subdirectories are part of the system logic and should not be changed for normal use.


1. Basic Concept
----------------

A flight path is described by one YAML file.

A YAML file can define:

- the name of the flight path
- the type of flight path
- movement distances
- movement speeds
- yaw angles
- yaw rates
- vertical movements
- ordered movement commands
- parameters for ideal path generation
- parameters for analysis

All YAML flight path files are stored in:

path_specs/

The program automatically searches this folder for files ending in:

.yaml
.yml

Every valid YAML file in this folder appears in the path selection menu.

This means that adding a new flight path only requires adding one new YAML file to path_specs/. No execution script has to be changed.


2. File Location
----------------

All YAML flight path files must be placed in:

path_specs/

Examples:

path_specs/circle_3m.yaml
path_specs/square_3m.yaml
path_specs/custom_turn_forward_up.yaml
path_specs/inspection_path_room_01.yaml

Recommended file naming:

circle_3m.yaml
square_3m.yaml
my_new_path.yaml
inspection_path_room_01.yaml

Avoid spaces and special characters in file names.


3. Creating a New YAML File
---------------------------

The easiest method is to copy an existing YAML file.

Example:

cp path_specs/circle_3m.yaml path_specs/my_new_path.yaml

Then edit the new file:

nano path_specs/my_new_path.yaml

At minimum, change the name field:

name: my_new_path

The name should be unique because it is shown in the menu and used in the analysis output folder.


4. YAML Formatting Rules
------------------------

YAML depends on correct indentation.

Use spaces, not tabs.

Correct:

parameters:
  speed_m_s: 0.3
  diameter_m: 3.0

Incorrect:

parameters:
speed_m_s: 0.3
diameter_m: 3.0

General rules:

- use spaces for indentation
- do not use tabs
- use two spaces per indentation level
- every key needs a colon
- decimal numbers use a dot, for example 3.0
- lists use a dash
- keep names simple
- avoid spaces in the name field

Example list:

commands:
  - action: forward
    distance_m: 2.0

  - action: yaw
    angle_deg: 90


5. Required YAML Structure
--------------------------

Each YAML file should contain:

name: example_path
type: command_sequence

description: Short explanation of the flight path.

parameters:
  speed_m_s: 0.3

Required fields:

name
Unique name of the flight path. This name is shown in the menu and used for result folders.

type
Type of flight path. Supported values are:

circle
square
command_sequence

description
Human-readable explanation of the path. This is optional but recommended.

parameters
General settings used for execution and ideal path generation.

commands
Only required for command_sequence. Defines the ordered movement steps.


6. Units
--------

All values must use the following units.

Distance:
meters

Examples:
distance_m: 2.0
diameter_m: 3.0
side_length_m: 5.0

Altitude:
meters

Example:
altitude_m: 1.0

Horizontal speed:
meters per second

Example:
speed_m_s: 0.3

Vertical speed:
meters per second

Example:
vertical_speed_m_s: 0.3

Angle:
degrees

Example:
angle_deg: -90

Yaw rate:
degrees per second

Example:
yaw_rate_deg_s: 22.5

Ideal path samples:
count

Examples:
samples: 1000
samples_per_side: 250

Ideal path resolution:
meters

Example:
step_size_m: 0.02


7. Motion Convention
--------------------

The YAML flight executor publishes velocity commands to:

/cmd_vel

Supported movement commands:

forward
backward
up
down
yaw

Yaw convention:

positive angle_deg = turn left / counter-clockwise
negative angle_deg = turn right / clockwise

Example:

- action: yaw
  angle_deg: 90

This means: turn left by 90 degrees.

Example:

- action: yaw
  angle_deg: -90

This means: turn right by 90 degrees.


8. Pitch and Roll
-----------------

Pitch and roll are currently not direct YAML commands.

Currently supported executable orientation command:

yaw

Currently not supported as executable YAML actions:

pitch
roll

Reason:

The current workflow controls the UAV through /cmd_vel. It sends translational velocity commands and yaw-rate commands.

Roll and pitch are internal attitude reactions generated by PX4 while the UAV moves. For example, when the UAV moves forward, PX4 may pitch the vehicle internally, but the user does not directly command pitch in the YAML file.

Use these commands to define the path:

forward
backward
up
down
yaw

Do not use pitch or roll as YAML actions unless the executor is extended later.


9. Supported Path Type: Circle
------------------------------

A circle path is used when the UAV should fly a circular trajectory.

Example:

name: circle_3m
type: circle

description: Circle with 3 meter diameter.

parameters:
  diameter_m: 3.0
  speed_m_s: 0.3
  direction: ccw
  altitude_m: 0.0
  samples: 1000

Fields:

diameter_m
Diameter of the circle in meters.

speed_m_s
Forward speed during execution.

direction
Circle direction.

Supported values:

ccw
cw
left
right

Meaning:

ccw = counter-clockwise
cw = clockwise
left = counter-clockwise
right = clockwise

altitude_m
Ideal relative altitude used for the ideal path. Use 0.0 if no altitude change is intended.

samples
Number of ideal path points generated for analysis. A typical value is 1000.


10. Supported Path Type: Square
-------------------------------

A square path is used when the UAV should fly four straight segments with 90 degree turns.

Example:

name: square_3m
type: square

description: Square with 3 meter side length.

parameters:
  side_length_m: 3.0
  speed_m_s: 0.3
  yaw_rate_deg_s: 22.5
  direction: left
  altitude_m: 0.0
  samples_per_side: 250

Fields:

side_length_m
Length of each square side in meters.

speed_m_s
Forward speed during execution.

yaw_rate_deg_s
Yaw rate used for the 90 degree turns.

direction
Turn direction.

Supported values:

left
right
ccw
cw

Meaning:

left = turn left
right = turn right
ccw = counter-clockwise
cw = clockwise

altitude_m
Ideal relative altitude used for the ideal path. Use 0.0 if no altitude change is intended.

samples_per_side
Number of ideal path points per square side. A typical value is 250.


11. Supported Path Type: Command Sequence
-----------------------------------------

A command sequence is used for custom paths.

It consists of a list of ordered commands.

Example:

name: custom_turn_forward_up
type: command_sequence

description: Turn right, fly forward 2 m, turn left 40 degrees, fly forward 5 m, climb 5 m.

parameters:
  speed_m_s: 0.3
  vertical_speed_m_s: 0.3
  yaw_rate_deg_s: 22.5
  step_size_m: 0.02

commands:
  - action: yaw
    angle_deg: -90

  - action: forward
    distance_m: 2.0

  - action: yaw
    angle_deg: 40

  - action: forward
    distance_m: 5.0

  - action: up
    distance_m: 5.0


12. Command Sequence Parameters
-------------------------------

speed_m_s
Horizontal speed for forward and backward.

vertical_speed_m_s
Vertical speed for up and down.

yaw_rate_deg_s
Yaw rate for yaw commands.

step_size_m
Resolution used to generate the ideal reference path for analysis. A smaller value creates a denser ideal path.

Typical value:

step_size_m: 0.02

This means the ideal path is sampled approximately every 2 cm.


13. Supported Command Actions
-----------------------------

The following actions are supported inside commands.

forward
Moves the UAV forward.

Example:

- action: forward
  distance_m: 2.0

backward
Moves the UAV backward.

Example:

- action: backward
  distance_m: 1.0

up
Moves the UAV upward.

Example:

- action: up
  distance_m: 1.5

down
Moves the UAV downward.

Example:

- action: down
  distance_m: 1.0

yaw
Rotates the UAV around the vertical axis.

Example:

- action: yaw
  angle_deg: -90


14. Using a YAML Flight Path
----------------------------

The basic system must be running first.

Typical startup order:

Terminal 1:
./scripts/simulation/start_agent.sh

Terminal 2:
./scripts/simulation/sim_environment_menu.sh

Terminal 3:
./scripts/camera/start_camera_bridges_all_worlds.sh

Terminal 4:
./scripts/control/start_tf_broadcaster.sh

Terminal 5:
./scripts/control/start_offboard_control.sh

Then use the YAML path menu.


15. Starting the Analyzer
-------------------------

Open a new terminal and run:

./scripts/flight/path_workflow_menu.sh

In the menu:

1. select the desired YAML file
2. select Start analyzer only

The analyzer records the actual UAV path from PX4 odometry.

The analyzer should be started before the flight execution.


16. Executing the Flight
------------------------

Open another terminal and run:

./scripts/flight/path_workflow_menu.sh

In the menu:

1. select the same YAML file
2. select Execute flight only

The executor reads the selected YAML file and publishes the corresponding velocity commands to:

/cmd_vel

After the flight is complete, return to the analyzer terminal and stop it with:

Ctrl+C

The analysis files are then generated automatically.


17. Analysis Output
-------------------

Each analysis run creates a separate timestamped folder:

path_analysis/YYYY-MM-DD_HH-MM-SS_NAME_OF_PATH/

Example:

path_analysis/2026-06-04_16-30-22_circle_3m/

The folder contains:

actual_path.csv
The recorded UAV path from PX4 odometry.

ideal_path.csv
The ideal reference path generated from the YAML file.

deviation_samples.csv
Per-sample deviation between recorded path and ideal path.

path_analysis_report.txt
Human-readable analysis report.

path_analysis_report.json
Machine-readable analysis report.

path_comparison_3d.html
Interactive 3D comparison of ideal path and recorded path. This file can be opened in a browser and rotated with the mouse.


18. Validation Checklist
------------------------

Before using a new YAML file, check:

- file is inside path_specs/
- file extension is .yaml or .yml
- name is unique
- type is circle, square, or command_sequence
- all distances are in meters
- all speeds are in meters per second
- all angles are in degrees
- command_sequence contains a commands list
- only supported actions are used
- indentation uses spaces, not tabs
- analyzer is started before the flight
- offboard control is running before flight execution


19. Common Problems
-------------------

Problem:
The YAML file does not appear in the menu.

Possible causes:
- the file is not inside path_specs/
- the file does not end with .yaml or .yml

Problem:
The YAML file cannot be loaded.

Possible causes:
- wrong indentation
- tabs instead of spaces
- missing colon
- invalid YAML structure

Problem:
The flight does not start.

Possible causes:
- offboard control is not running
- PX4/Gazebo is not running
- wrong terminal
- multiple control modes are running at the same time

Problem:
The analysis has too few samples.

Possible causes:
- analyzer was started after the flight
- analyzer was stopped too early
- odometry was not available

Correct sequence:
Start analyzer first, execute flight second, stop analyzer after the flight is complete.


20. Final Rule
--------------

New flight paths are added by creating new YAML files in:

path_specs/

Do not edit the execution scripts for normal use.

The intended workflow is:

1. create or copy a YAML file
2. place it in path_specs/
3. select it in path_workflow_menu.sh
4. start analyzer
5. execute flight
6. stop analyzer
7. inspect generated analysis output
